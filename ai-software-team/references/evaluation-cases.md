Validator regression coverage must include: root-only Lean; Lean child writes/risk/non-L1 failures; valid and incomplete Balanced; valid and incomplete Assurance chain; explicit low-risk Luna/low and high-risk Sol/xhigh routes; Luna preference warnings and safety-boundary exemptions; removed or external model rejection; all six effort prefixes; invalid prefix/case/minimal/missing effort; invalid `all`/`default` forks and unjustified finite history; v1/v2 migration error; external/legacy names; role-duty mismatch, self-review, overlapping writes, dependency order, and risk specialist activation.

Also cover Astra ordinary and critical routes, mixed Sol/Astra judgments, unsupported Astra effort, Astra prefix/receipt mismatch, Security Reviewer/Devil's Advocate below high outside Assurance, Luna outside Balanced or with non-low axes or judgment roles, uncommon eligible pairs, and both critical-hold strings with no safe route versus an available Astra high+ route. Root identity and respect for user choice require independent scenario evaluation; passing the Python suite alone does not prove those behaviors. Evaluation fixtures simulate runtime evidence and must not be presented as actual launches or account capabilities.

For generation upgrades, retain the legacy-only fixture suite and add new-only and mixed-generation cases: ordinary and critical routes for both new Sol IDs; both Luna generations' duty/assessment/mode limits; family preference warnings; unsupported or missing exact runtime pairs; new-Luna ultra rejection; invalid future IDs; both critical-hold markers with a new Sol high-plus route; and cross-generation receipt mismatch despite identical prefixes. Keep these fixture results distinct from live launcher tests.

## Cost gates

Use fixed prompts to compare quality evidence with child count and inherited-context turns. A localized all-low L1 should target **0 children**. An ordinary L2 should target **two children** when a read-only QA + Code Reviewer can safely merge after the builder. Assurance has no artificial child cap: preserve every independent risk gate. Do not trade away test, challenge, or final-review independence merely to reduce cost.

Within a team that already passes those gates, compare eligible Luna discovery routes with the corresponding Terra baseline. Prefer Luna only after acceptance quality passes; track first-pass success, reviewer-requested rework, total wall time, and credits or the available proxies. A higher Luna call count is never itself evidence of improvement.

For workflow-only comparisons, freeze the prior baseline and keep model/effort, environment, and quality gates constant. For model/effort comparisons, change the selected route while holding prompts, inputs, environment, and quality gates constant. Compare costs only for runs passing those gates. If credits are unavailable, report proxies such as child turns, follow-ups, inherited context, and tool calls; do not claim that credits improved from proxies.

Distinguish call frequency (a combination's observed calls divided by all child calls in the sample) from routing suitability. Report sample size and task mix separately from user-selected root configurations. Track first-pass acceptance, capability-driven escalation/rework, elapsed time, and measured resource use. A successful run demonstrates sufficiency, not that a cheaper route would fail; test that with matched comparisons. Do not invent future percentages, force every eligible combination to be used, or equate more calls to one model with improved efficiency.
